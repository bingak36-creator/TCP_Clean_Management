# 공식 ESP32 장치 인증과 영속 전송 큐

SERVER 모드는 등록된 MAC의 인증 키를 사용합니다. 공유 환경 변수 키는 사용할 수 없습니다. 기존 펌웨어는 새 버전과 설정으로 전환해야 합니다.

## 설정

1. 개발자 세션으로 장치 MAC의 Device Set을 등록하거나 기존 Upstash 등록을 확인합니다.
2. 시스템 설정의 장치별 인증 키 발급 버튼 또는 `POST /api/admin/device-credentials/{mac}/rotate`로 키를 발급합니다. 이 키는 응답 시 한 번만 표시합니다. 재발급·폐기·MAC 교체 시 이전 키는 사용할 수 없습니다.
3. `device_config.example.h`를 Git에서 제외되는 `device_config.h`로 복사하고 `TCP_SERVER_ROOT_CA`에 HTTPS 서버의 루트 CA PEM을 C 문자열로 넣습니다. 키를 이 헤더나 Git에 넣지 마세요.
4. 펌웨어를 컴파일·업로드합니다. BOOT 버튼을 누른 채 부팅하거나 3초 길게 눌러 포털을 열고, 시리얼 로그에 표시되는 일회용 AP 비밀번호로 `ESP32_Setup`에 접속합니다.
5. `192.168.4.1`에서 서버 HTTPS 호스트·443 포트·해당 MAC의 키를 저장합니다. 키는 NVS에 보관하며 저장된 키를 포털 HTML로 돌려주지 않습니다. 빈 입력은 기존 키를 유지합니다.
6. 설정 조회 200과 센서별 전송 201을 확인합니다. `X-Device-Mac`과 `X-Device-Key`는 펌웨어가 함께 전송합니다. 잘못되거나 폐기된 키는 401, 다른 MAC·센서는 403, 비활성 센서·구역의 새 입력은 409입니다.

공인 HTTP로 장치 키를 전송하지 않습니다. 신뢰하는 개발 LAN에서만 `TCP_ALLOW_LAN_HTTP true`를 명시하면 RFC1918의 IP 리터럴에 HTTP를 허용합니다. HTTPS는 서버 인증서를 검증하고 리디렉션을 따르지 않습니다. 서버 CA와 NTP 접속이 필요합니다. 기본 서버 호스트는 비어 있고 포트는 443이므로 첫 부팅 시 포털에서 실제 HTTPS 호스트를 입력합니다. 이미 설치된 장치는 NVS에 저장된 주소를 계속 쓰므로 포털에서 다시 저장해야 합니다.

```sh
arduino-cli compile --fqbn esp32:esp32:esp32 arduino/esp32_dht22_mq7
arduino-cli upload --fqbn esp32:esp32:esp32 --port /dev/cu.usbserial-0001 arduino/esp32_dht22_mq7
```

## 영속 큐의 동작과 한계

- 한 번의 측정에 같은 UTC 측정 시각과 패킷 키를 사용하고 센서별 요청을 한 파일에 저장합니다. 네트워크 전송 전에 LittleFS의 임시 파일 작성·flush·rename을 끝냅니다.
- 성공 확인을 받은 센서만 원자적 갱신으로 제거합니다. 전원 중단이 확인 응답과 파일 갱신 사이에 발생하면 동일 키로 재전송하므로 서버가 측정 행을 중복 생성하지 않습니다.
- 부팅 시 남은 패킷을 복구합니다. 처음 쓰는 파티션만 초기화하며, 이전에 사용한 큐가 마운트되지 않으면 자동 포맷하지 않습니다. 깨진 패킷은 `/qbad.pkt`(가장 최근 1개)로 옮겨 진단용으로 남기고, 뒤 패킷 전송을 막지 않습니다.
- 서버 응답에 따라 처리합니다. 연결 실패·설정 오류·401·408·429·5xx는 보존 후 재시도합니다. 400·403·404·409처럼 다시 보내도 성공할 수 없는 응답은 해당 측정값만 폐기하고 시리얼 로그를 남깁니다. 403·404를 받으면 다음 측정부터 최신 센서 ID를 쓰도록 설정을 다시 조회합니다. 비활성 구역(409)의 측정값도 서버가 거부하므로 폐기됩니다.
- 기본 한도는 720패킷·768KiB이며, 파일 크기와 파일시스템 공간에 따라 먼저 한도에 도달할 수 있습니다. 5초 주기에서는 최대 약 1시간 분량입니다. 가득 차면 미확인 데이터를 지우지 않고 새 측정을 대기하며 시리얼 로그로 알립니다. 실제 파티션 용량도 확인하세요.
- 통신 복구 후 약 3초 간격으로 패킷을 비웁니다. 전송 실패는 재시도하며, 설정 오류·폐기된 키·센서 교체는 운영자가 바로잡아야 합니다. 큐는 무한 저장소가 아닙니다.
- 통신 단절 중에도 마지막으로 확인한 센서 ID와 이미 동기화된 시계로 수집합니다. 전원이 완전히 꺼진 뒤 정확한 시각을 복구하지 못한 부팅에서는 NTP 동기화 전 새 측정을 기다립니다. 이미 저장된 패킷의 시각은 바꾸지 않습니다.
- 큐와 키는 일반 플래시에 저장합니다. 물리적 플래시 추출 방어와 실제 전원 차단·복구 시험은 별도 하드웨어 검증입니다.

큐 코어는 스케치와 같은 `DurableQueue.h`를 사용해 호스트에서도 검증합니다.

```sh
clang++ -std=c++17 arduino/esp32_dht22_mq7/tests/durable_queue_test.cpp -o /tmp/tcp-queue-test
/tmp/tcp-queue-test
```

SUPABASE 모드는 별도 전송 경로입니다. 장치별 키·영속 큐는 SERVER 모드에만 적용합니다. Supabase 전송은 `device_config.h`의 `TCP_SUPABASE_ROOT_CA`로 인증서를 검증하며, 비어 있으면 전송하지 않습니다. 외부 DB 접근 정책(RLS 등)은 별도로 확인해야 합니다.

### GPS 및 장치 발견 (seokhyeon09 main 통합)

설정 포털에서 위도·경도를 입력하면 NVS에 저장합니다. 스마트폰 GPS 버튼은 브라우저 보안 정책상 HTTP 포털에서 차단될 수 있으며 웹 관리 화면의 지도 또는 수동 입력을 사용할 수 있습니다. 좌표는 장치 키로 인증된 위치 API에 한 번 보내고 성공 전 30초마다 재시도합니다.

키가 없는 새 장치도 서버 주소와 TLS CA가 설정되어 있으면 30초마다 발견 정보만 알릴 수 있습니다. 개발자가 현장 MAC/GPS를 확인해 등록한 뒤 장치별 키를 발급하고 포털에 저장해야 센서 설정 조회·측정 전송이 허용됩니다. BOOT 버튼으로 설정 포털을 다시 열 수 있습니다. 발견 목록은 서버 재시작 시 사라지며 장치 신원을 보증하지 않습니다.
