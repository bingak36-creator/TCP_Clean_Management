# 프론트엔드 통합 및 ESP32 직접 수집 검증

검증일: 2026-10-12. UI 원본은 `hyunminboo/TCP_Clean_Management`의 `frontend` 브랜치 커밋 `162daaa2b4ab342ec07dcfccffc2562b27963f36`입니다.

## 자동 검사

- 백엔드: H2의 MySQL 호환 모드로 전체 테스트 **35개 통과**, 실패·오류·건너뜀 0개. 테스트는 별도 임시 DB를 사용하며 실제 MySQL 이력을 삭제하지 않았습니다.
- `bootJar` 빌드 통과.
- 프론트엔드 `npm run build` 통과. 번들 크기 경고가 남아 있습니다.
- `npm run lint` 종료 코드 0. 원본 UI의 React Hooks·미사용 선언 등 경고가 남아 있습니다.
- `git diff --check` 통과. 로컬 DB 비밀번호·Upstash 연결 정보·장치 키가 변경 파일에 포함되지 않는지 확인했습니다.
- ESP32 코어 3.3.12, `esp32:esp32:esp32` 대상으로 펌웨어 컴파일 및 실제 업로드 통과. 업로드 후 플래시 해시 검증 통과.

## 실제 기기와 MySQL 검증

1. 연결된 ESP32의 기존 4MB 플래시를 로컬 비공개 폴더에 백업했습니다. Wi-Fi 설정이 들어 있을 수 있어 저장소에 포함하지 않았습니다.
2. 직접 전송 펌웨어 적용 후 시리얼에서 `POST MySQL API -> 201`과 해당 센서 패킷을 확인했습니다.
3. 시리얼에서 확인한 JSON과 MySQL에 보관된 원본 JSON이 정확히 일치했습니다. 온도·습도·MQ-135 측정 항목 3개가 함께 저장됐습니다.
4. 같은 실제 패킷을 재전송했을 때 HTTP 200과 `duplicate=true`를 반환했으며, 해당 샘플의 원본은 1행, 측정 항목은 3행으로 유지됐습니다.
5. 백엔드를 재시작하고 `UPSTASH_SYNC_ENABLED=false`, `RATE_LIMIT_STORE=memory`로 설정한 뒤에도 후속 실제 패킷이 `ingest_source=direct_api`로 계속 저장됐습니다. 이전 Upstash 이력도 보존됐습니다.
6. 장치 키가 없는 POST는 HTTP 401, MySQL 조회 API의 `source=upstash` 요청은 HTTP 400이었습니다. MySQL 최신 조회 응답은 `source=mysql`, `ingestSource=direct_api`, `stale=false`였습니다.
7. 공개 구역 API도 Redis 연결 없이 로컬 메모리 요청 제한을 사용하며 HTTP 200을 반환했습니다.

## 브라우저 검증

- 실제 MySQL 온도·습도·MQ-135 값과 시간 이력 차트 표시 확인.
- MySQL 조회 표시만 남고 Upstash 직접 조회 버튼이 제거된 상태 확인.
- 관리자·개발자·청소 담당자 시연 로그인과 역할별 화면 확인.
- 1시간·6시간·7일 이력 전환 확인.
- 원본 출동 팝업 열기·닫기 확인. 실제 외부 메시지를 발송하지 않았습니다.
- 지도 JavaScript 키가 없는 환경에서 안내 및 대시보드 이동 링크 표시 확인.

## 검증 범위와 제한

실제 계정 인증, 청소·출동·시설 설정의 서버 저장은 아직 연결하지 않았습니다. 해당 화면은 시연 기능으로 표시합니다. 지도 키 및 설치 좌표가 없어 실제 지도·길찾기 동작은 검증하지 않았습니다. Docker 데몬이 실행되지 않아 컨테이너 실행 검증은 하지 않았습니다.

직접 수집은 개발 LAN의 백엔드가 켜져 있을 때 동작합니다. ESP32의 확인되지 않은 패킷은 RAM에 보관하고 같은 키로 재전송하며, 전원 차단 시 그 패킷이 사라질 수 있습니다. 기기 인증 키·Wi-Fi 정보·실제 센서 패킷 및 화면 캡처는 로컬에만 보관하고 이 문서에는 포함하지 않았습니다.
