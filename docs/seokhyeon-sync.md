## 기존 보안 및 데이터 처리와 맞춘 부분

- 서버 발급 세션, BCrypt 비밀번호, 역할·구역별 권한, 요청 제한을 유지했다.
- 장치 설정·측정값·위치 변경은 장치별 키를 확인한다. 위치 API의 URL MAC은 인증된 장치 MAC과 같아야 한다.
- 미등록 장치가 보내는 MAC/IP/GPS는 확인 전 정보다. 등록·키 발급·센서 설정 공개를 자동으로 수행하지 않는다. 개발자가 현장 정보를 대조하고 등록해야 한다.
- 발견 정보는 프로세스 메모리에서 최대 512개, 마지막 수신 후 24시간 동안 보관한다. 재시작하면 사라진다. IP별 IoT 요청 제한을 적용한다.
- 장치 MAC 변경 시 이전 장치 키를 비활성화하는 기존 동작을 유지했다. 새 MAC의 키는 별도로 발급하여 해당 ESP32에 설정한다.
- 측정·알림·AI 이력이 연결된 시설·장치·센서를 원본 코드의 일괄 삭제 방식으로 지우지 않는다. 참조된 데이터는 409 응답으로 보호하고 비활성화할 수 있다.
- 새 계정에 1234 같은 비밀번호를 자동으로 넣지 않는다. 최소 12자/최대 72 UTF-8 byte 정책을 유지한다.
- backend/ai의 모델·실행 파일 17개와 AuthService/AuthContext는 통합 전 백업과 바이트 비교 결과 동일했다. 기존 실제 모델 5개와 AI 결과 처리 경로를 보존했다.
- ESP32의 TLS CA 검증, 장치별 키, 무작위 설정 AP 비밀번호 및 영속 재전송 큐를 유지했다.

## DB 적용

새 파일: backend/src/main/resources/db/migration/V3__zone_worker_assignment.sql

- zones에 assigned_worker_id, assigned_worker_name을 추가한다.
- 기존 worker의 구역 배정을 구역 정보로 반영한다. 동일 구역에 기존 담당자가 여러 명이면 가장 작은 ID를 대표 담당자로 사용하며 기존 worker 행은 삭제하지 않는다.
- sensors.status에 INACTIVE를 추가한다.
- V2까지 적용한 DB는 다음 실행 시 V3가 적용된다. 운영 DB를 이 작업에서 직접 갱신하지 않았다.
- 버전 관리가 없는 기존 DB에는 임의 baseline을 실행하지 말고 security-upgrade.md의 백업·검증 절차를 따른다.

## 승인 대기 항목

원본의 retention_days 설정 및 보관기간에 따른 원본·Upstash 패킷 자동 삭제 확대는 적용하지 않았다.
자동 승인 검토가 측정 데이터 손실 범위에 대한 명시적 승인이 부족하다는 이유로 변경을 거절했다.

현재 코드는 기존 원본 데이터 7일 정리 정책을 유지한다. 새 Upstash 패킷 자동 삭제나 기간 변경은 추가하지 않았다.
화면에서도 변경되지 않은 7일 정책을 표시한다.

검토 대상 원본: https://github.com/seokhyeon09/TCP_Clean_Management/commit/3d3ecc4
승인할 구체적 범위는 기간을 정수 1~3650일로 설정하고 그 기간을 넘긴 원본 및 Upstash 패킷을 정기적으로 삭제하는 기능이다.
새 설정의 기본값은 기존 동작과 같은 7일로 유지하는 안이다.
